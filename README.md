# Legal Navigator — Telegram Mini App

Frontend for an assistant that answers questions about a corporate legal handbook. It is a thin client with no model, prompt or search of its own: the app sends the question to n8n and renders whatever the workflow returns.

The handbook content and the Mini App interface are in Russian.

**Open:** https://knyazkovstudios1.github.io/legal-navigator-miniapp/

## Two modes

| Mode | When | What happens |
|---|---|---|
| Live | By default | The app sends each question straight to the n8n workflow at `CHAT_URL` (set in `app.js`): the workflow's production chat webhook, hosted on Railway |
| Demo | When the response is not JSON or the request fails | Answers are taken from `demo-responses.json` and, for other questions, from the ready-made answers in `catalogue.json`. `demo-responses.json` was generated by running the **real** n8n Code nodes (guardrail and visualization), so the interface behaves exactly the same, just without a live Qdrant search |

Demo mode switches on automatically, stays on for the rest of the session and openly announces itself with a banner at the top. The app checks the content type rather than the status code because a static host such as GitHub Pages answers a POST with 405, not 404.

## Three behavior branches

In the Russian UI the branches are labeled А, Б and В (the first three letters of the Russian alphabet); the response data keys them as `A`, `B` and `V`.

- **A** — a direct answer with a reference to the specific clause of the handbook.
- **B** — action required: a draft email is prepared, and it is sent **only** after a human approves it in a Telegram chat. The app receives its response immediately, before the workflow pauses for approval, and shows a pending status.
- **V** — the document gives no direct basis for an answer, so the question is passed to a lawyer. No visualization is shown in this branch at all: a chart next to "not confirmed by the knowledge base" would read as an answer.

## Tabs

- **Chat** ("Чат") — questions and answers. Suggestions from a catalogue of ready-made questions (`catalogue.json`) appear as you type and after each answer, and you can ask for a chart built from a table in the handbook.
- **Threshold** ("Порог") — enter a contract amount and tick any non-price triggers from §4.1 to see who signs under the authority matrix, whether legal sign-off is needed, and every handbook rule that applies, including conflicts between sections.
- **Quiz** ("Квиз") — ten random questions from a bank generated from the handbook's tables (`quiz.json`); every correct answer is a verbatim cell from the document, shown with its clause reference.
- **Requests** ("Заявки") — the request log kept in the n8n workflow: each question with its answer, branch and source. Requests can be moved between statuses and filtered to those that need a human. The tab opens only with an access key, which is stored in the browser of whoever entered it.
- **Document** ("Документ") — the handbook itself, rendered from `doc.json`.

## Optional Vercel proxy (`api/ask.js`)

`api/ask.js` is an optional Vercel serverless function that can verify Telegram `initData` and forward the question to n8n. It is not used by the current GitHub Pages deployment.

To deploy it:

```bash
npx vercel --prod
```

Then, under Settings → Environment Variables:

| Variable | Value |
|---|---|
| `TELEGRAM_BOT_TOKEN` | The bot token from BotFather |
| `N8N_CHAT_URL` | The Production Chat URL of the Chat Trigger node |

Do not set `ALLOW_ANONYMOUS` in production: it disables the signature check.

The bot token lives only in environment variables. Never put it in an n8n Code node: the node's source code is included verbatim in the workflow export.

## Connecting to the bot

BotFather → `/mybots` → your bot → Bot Settings → Menu Button → Configure menu button → paste the URL → set the label to `⚖️ Навигатор` (Russian for "Navigator").

Do not set your own `setWebhook` on the bot: Telegram allows only one webhook per bot, and a second one would break the approval flow from n8n. The menu button does not need a webhook.
